## The Overwrite Bug

Git history reveals a destructive sequence repeating every morning:

1. **~05:50 UTC**: `daily report: YYYY-MM-DD morning briefing` -- a briefing with structured content is committed.
2. **~06:15 UTC**: `daily: YYYY-MM-DD morning scaffold` or `Scaffold daily note YYYY-MM-DD` -- an empty template overwrites the briefing.

Example from Aug 22:
- [05:46](https://github.com/westsoever/cos/commit/e41898c19c6ad4cebd0416ceb0a0f498eaa3668d) -- briefing committed.
- [06:17](https://github.com/westsoever/cos/commit/4b44e3e2da88113590ebe7d26b61c4c3255c0a0e) -- empty scaffold replaces it.

The briefing contains the only structured daily data the system produces, and it is destroyed before the weekly synth can read it. This is the root cause of five weeks of empty notes.

## Experiments for Next Week

Given the overwrite bug is the single biggest blocker, the experiments must fix the pipeline rather than add new tracking:

1. **Fix the overwrite sequence.** The /daily-brief skill and the scaffold script are racing. Options: (a) merge the briefing into the scaffold so the final file contains both, (b) have the scaffold append to the file instead of overwriting, or (c) commit the briefing to a separate path (e.g., `01-Daily/briefings/`) that the scaffold never touches. Any of these would finally produce readable daily data.

2. **Move carry-overs to a real backlog.** Create `02-Projects/backlog.md` and link it from daily notes instead of listing items. If a task survives 72 hours without action, it goes to the backlog. Daily notes should only list items planned for *that day*.

3. **One-line git commit message as a proxy.** If fixing the overwrite bug is blocked, append one line to the daily note's YAML before the scaffold commits it: `brief_summary: "Orbit source published; 2h Brella data work"`. This uses the existing commit infrastructure and takes 10 seconds. The weekly synth can then at least see what happened each day.
